## Key Concepts I Learned

- Azure Key Vault provides a secure way to store and manage sensitive information such as secrets, encryption keys, and certificates instead of keeping them directly in application code or configuration files.
- I learned how Azure RBAC can be used to control access to Key Vault resources and assign users or applications only the permissions they require.
- Soft Delete and Purge Protection help protect important Key Vault objects from accidental or unauthorized deletion.
- Network security can be improved by using firewall rules, virtual networks, and private endpoints to restrict how Key Vault can be accessed.
- Key and secret management is a continuous process that includes creating, protecting, rotating, monitoring, and retiring keys when they are no longer required.
- I also learned how Microsoft Defender for Cloud can help identify suspicious activities and potential security risks.

## My Takeaways

Azure Key Vault is an important service for protecting sensitive information in cloud environments. One of the major things I learned is that credentials, API keys, passwords, and other secrets should not be unnecessarily exposed or hardcoded in applications.

I also gained a better understanding of how RBAC and the principle of least privilege can be used to control access to sensitive resources.

Another important takeaway is that securing Key Vault requires multiple layers of protection. Access control, network security, data protection, key management, and monitoring should work together rather than relying on a single security measure.

Even though I could not complete the hands-on lab, the learning path gave me a clearer understanding of how Key Vault can be incorporated into a secure Azure environment.
